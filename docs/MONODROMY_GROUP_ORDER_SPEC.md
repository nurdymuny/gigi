# MONODROMY_GROUP_ORDER: bounded SU(2) closure

Contract frozen before implementation, 2026-11-17. The initial gate status was
NOT RUN. Current acceptance status and retained evidence are recorded separately
in `MONODROMY_GROUP_ORDER_RESULTS.md`; this contract alone does not close a gate.

## Purpose and scope

Move subgroup enumeration, multiplication-table verification, element orders,
and optional derived-subgroup closure into GIGI. The client supplies generators;
it does not enumerate products. The flagship is the binary icosahedral generator
pair versus an identity control, with independently expected orders 120 and 1.
The same implementation must handle cyclic, quaternion, and tetrahedral groups.
No Poincare proof, manifold recognition, triangulation ingestion, BETTI extension,
or general gauge invariance is claimed. Independent gauge changes at unrelated
edge endpoints can change this result; simultaneous conjugation cannot.

## Mathematical contract

For supplied scalar-first unit quaternions S, compute the subgroup generated by
S and its inverses using existing GroupElement::compose/inverse. GIGI's convention
has vector cross-product term -a cross b. Never identify q with -q: SU(2) is not
SO(3). Identity is (1,0,0,0). Input unit-norm residual must be <= 1e-10;
accepted inputs are normalized once in the private query snapshot, with the
maximum input norm residual disclosed. Nonfinite/zero/nonunit inputs refuse.

Floating-point input alone cannot certify exact finiteness of the intended real
subgroup. Successful status is `numerically_closed`, not an exact SU(2) theorem.
`group_order` is the order of the checked finite multiplication table approximating
the supplied generators, and `exact_subgroup_certified` is always false.

Metric: Euclidean chord distance on R^4, with no antipodal quotient. Match an
element only when exactly one representative is within tolerance. Any additional
representative within 8*tolerance, or a nearest distance in (tolerance,
8*tolerance], makes the computation unresolved rather than silently merging it.
No decimal-bin hashing, trace-only equivalence, or continued-fraction order guess.

Algorithm:
1. Start at identity; deterministic breadth-first traversal by generators and
   inverses in input order. Retain unrounded representatives.
2. If adding a new representative would exceed CAP, return unresolved.
3. Build the complete n*n product table with unique tolerance matches. Verify
   identity, two-sided inverses, and associativity for every triple of indices.
   Missing/ambiguous products or failed axioms return unresolved.
4. Derive element orders by repeated TABLE multiplication (not arccos).
5. With COMMUTATOR, enumerate all a*b*a^-1*b^-1 using the checked table and close
   the subgroup they generate. Return its order, perfection, and quotient order.

The finite table's group axioms are checked discretely; its embedding into SU(2)
is approximate. Report maximum product-to-representative residual, minimum
representative separation (null for the trivial group), product count, and
associativity checks. These are evidence, not statistical confidence intervals.

## Native interface

```sql
MONODROMY_GROUP_ORDER field FROM EDGES (0, 3) COMMUTATOR CAP 256 TOLERANCE 0.00000001;
```

Optional clauses may occur in any order, each at most once. Defaults: CAP 256,
tolerance 1e-8, no commutator calculation. Limits: 1..32 generator edges,
CAP 1..256, tolerance finite in [1e-12,1e-6]. Unknown clauses, duplicate options,
fractional/negative caps, empty lists, invalid edges, missing fields, and non-SU(2)
fields refuse with actionable messages. `gauge` feature required (`halcyon`
includes it). Feature-off execution must refuse, never return bare status:ok.

FROM EDGES reads the selected forward edge elements as generators. It does not
assert these are loops, that they generate pi_1, or that the host lattice is Sigma.
Those are caller-supplied modeling assumptions. A single Arc registry handle is
retained for the complete request; generators are copied before enumeration.
No source bundle mutation, persistent state, or result cache is introduced.

Return one ordinary GQL row. Fields:
- status: numerically_closed or unresolved; reason: null or actionable text.
- group_order: integer only on verified closure, otherwise null.
- n_elements_observed, generator_edges, generator_count, cap, tolerance.
- group_used: SU(2); exact_subgroup_certified: false; table_verified: boolean.
- element_orders and element_order_counts: parallel numeric arrays, ascending
  orders. This avoids extending GIGI's scalar/vector Record type for one verb.
- commutator_subgroup_order, is_perfect, abelianization_order: null unless
  COMMUTATOR requested and the full table accepted.
- max_input_norm_error, max_closure_residual, min_element_separation,
  products_evaluated, associativity_checks.
- scope: supplied_generator_subgroup; numerical_policy: su2_closure_v1.

On unresolved output, order/histogram/perfection fields carry no partial answer.
Refusals follow existing GQL error transport; an execution 500 is not a crash.
Invalid request and unresolved numerical calculation are different outcomes.
Both in-process execute and HTTP dispatch must reach the SAME kernel before
bundle lookup; no new REST route, global Record changes, or dependency required.

## Resource policy

The old proposal suggested CAP 512. Version 1 deliberately caps at 256 because
it checks all table triples. Storage O(CAP^2 + generator_count*CAP); matching
and associativity work O(CAP^3), with hard bounds independent of source size.
Only selected generator values are copied; no full bundle or field-buffer clone.
Increasing these bounds requires a new tested resource contract.

Evidence verifier must invalidate any earlier PASS before reading current evidence,
reject missing/corrupted/mismatched evidence, and publish PASS atomically only when
every required comparison succeeds. Malformed raw JSON and altered numerical
answers must not leave a stale PASS. Preserve red/green/mutation/live receipts.
