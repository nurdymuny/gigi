# MONODROMY_GROUP_ORDER: 120 versus 1

Date: 2026-11-17. Release gate: OPEN pending an end-to-end rerun after a
validation-build isolation repair. Both full Rust suites passed, all six
mechanism removals were detected, and a clean recovery build passed all 17 live
cases. The earlier combined runner correctly refused its contaminated final
binary; no overall `gate.PASS.json` was published.

## What GIGI now computes

One native GQL statement closes the subgroup generated by selected SU(2)
elements, checks its full multiplication table, computes element orders, and
optionally computes the derived subgroup. The application supplies generators;
it does not enumerate the group and upload a precomputed answer.

```sql
MONODROMY_GROUP_ORDER mg_icosahedral FROM EDGES (0,1)
  COMMUTATOR CAP 120 TOLERANCE 0.00000001;

MONODROMY_GROUP_ORDER mg_identity FROM EDGES (0)
  COMMUTATOR CAP 1 TOLERANCE 0.00000001;
```

These field names are created by the reproducible demonstration, on its own
private server and temporary data directory. No existing shared server or
production bundle is changed. The fields are prescribed generator fixtures,
not claimed manifold triangulations or measured sensor data.

## The mathematical example

Use scalar-first unit quaternions, with GIGI's existing minus-cross-product
composition convention:

```text
phi = (1 + sqrt(5))/2
s = (1/2, 1/2, 1/2, 1/2)
t = (phi/2, 1/2, (phi-1)/2, 0)
identity = (1, 0, 0, 0)
```

For the exact algebraic generators, s^3 = t^5 = (s*t)^2 = -identity.
The independent oracle works with rational coefficients in Q(sqrt(5)), not
GIGI's floating-point arithmetic. It verifies the 120-element closure, its
element-order histogram, and its 120-element derived subgroup. GIGI receives
ordinary floating-point approximations to these generators.

Observed in the isolated preflight run:

| Supplied generators | Table order | Derived subgroup order | Abelianization order |
|---|---:|---:|---:|
| Binary icosahedral pair s,t | 120 | 120 | 1 |
| Identity control | 1 | 1 | 1 |
| Central -identity | 2 | 1 | 2 |
| Cyclic order-five generator | 5 | 1 | 5 |
| Quaternion generators | 8 | 2 | 4 |
| Binary tetrahedral generators | 24 | 8 | 3 |
| s alone | 6 | 1 | 6 |
| t alone | 10 | 1 | 10 |

Reordered, simultaneously conjugated, redundant, and inverse-replaced
icosahedral generators each gave 120, with derived order 120. CAP 119 on the
same pair returned `unresolved`, null orders, and an actionable reason. An
irrational-angle rotation exhausted CAP 32 and likewise returned no finite
order. Missing fields, invalid edge indices, and U(1) fields refused.

For the 120-element case the observed histogram was:

```text
element orders:  1, 2,  3,  4,  5,  6, 10
counts:         1, 1, 20, 30, 24, 20, 24
```

GIGI evaluated 14,880 quaternion products, including all 14,400 table entries,
and checked all 1,728,000 associativity triples. Maximum closure residual was
4.742874840267547e-16; minimum representative separation was
0.6180339887498946, against tolerance 1e-8. The identity case needed three
quaternion products and one associativity check.

## Why this is useful

The two flagship cases both have abelianization order one. That summary alone
cannot distinguish them. The new operation retains the multiplication structure
and separates a nontrivial perfect group of order 120 from the trivial group.
Smaller groups and generator-removal controls demonstrate the same general
algorithm, not an answer keyed to this particular example.

For researchers working with supplied transport or monodromy representations,
this moves subgroup analysis into the database query surface, with explicit
caps, numerical diagnostics, and unresolved outcomes. Establishing that supplied
elements really are based-loop holonomies, that a representation is faithful,
or that they describe a particular manifold remains a separate modeling task.

Every successful numerical response says `numerically_closed`,
`table_verified: true`, and `exact_subgroup_certified: false`. The finite table
satisfies discretely checked group axioms; its embedding into SU(2) is approximate.
No Poincare proof, arbitrary manifold recognition, or performance advantage is
claimed. Simultaneous conjugation is tested; arbitrary independent gauge changes
at unrelated edge endpoints are not an invariance of this input contract.

## Reproduction

From the repository, with Rust/Cargo and Python 3 installed:

```powershell
python scripts/monodromy_gate.py --output output/monodromy-replay --target-dir C:\Users\nurdm\.cache\gigi-monodromy-target
```

The runner serially executes full default and `halcyon` Cargo suites, six
mechanism-removal checks in an isolated copy, an explicit server build, 17 live
cases, adversarial evidence tests, and a diff check. It pins source and binary
hashes, refuses a changed source snapshot, and publishes `gate.PASS.json` only
after every stage succeeds. Do not run another build against that target
directory at the same time on Windows.

To run only the live demonstration with a freshly built binary:

```powershell
cargo build --features halcyon --bin gigi-stream --target-dir C:\Users\nurdm\.cache\gigi-monodromy-target
python e2e/probes/monodromy_group_order_demo.py --binary C:\Users\nurdm\.cache\gigi-monodromy-target\debug\gigi-stream.exe --output output/monodromy-live-replay
```

`live.json` retains every request, raw response, parsed response, exact oracle
output, source hashes, and binary hash. The verifier invalidates its previous
PASS before reading input and refuses missing cases, altered answers, conflicting
raw/parsed data, false exactness claims, nonfinite values, and changed files.
The adversarial test changes both raw and parsed answers together, so a raw-copy
mismatch cannot substitute for validating the actual mathematics.

## Read-aloud walkthrough

"I give GIGI two quaternion generators, not a list of 120 answers. One query
builds their closure, checks the multiplication table, and finds 120 elements.
The same query on the identity finds one. Both have trivial abelianization,
so that simpler summary misses the distinction. GIGI preserves it. If I take
away a generator, the answer changes to six or ten; if I stop the search too
early, GIGI says unresolved. The numerical result agrees with an independent
exact-arithmetic calculation, while clearly stating the limits of floating-point
evidence."
